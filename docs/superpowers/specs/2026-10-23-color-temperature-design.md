# MonitorLight 冷暖调节设计

## 范围

在现有 macOS 菜单栏应用中加入针对所选外接显示器的相对冷暖调节，保持亮度功能、显示器选择与快捷键不变。

## 方案选择

采用现有 m1ddc 的红、绿、蓝硬件增益控制。与新增 VCP 色温预设命令相比，无须扩展底层工具；与软件 gamma 滤镜相比，不改变系统颜色管线，但依赖显示器支持硬件 RGB 读写。此版本不加入软件滤镜后备方案，也不声称精确校准色温。

## 交互与状态

- 在亮度区下增加“冷暖调节”滑块（偏暖—标准—偏冷），提供三个预设和“恢复原色”。不显示未经校准的 Kelvin 数字。
- 每次选择或检测显示器时，只读取 RGB 当前值与最大值，不自动写入。RGB 状态与亮度状态独立，读取失败不影响亮度。
- 每个显示器首次主动调色前保留原始 RGB 三通道值，并按显示器 UUID 保存到本机，跨重启可恢复。标准预设等同于恢复该基线；不覆盖用户已保存的基线。
- 相对基线调节：暖端保留红色、适度降低绿色和蓝色；冷端保留蓝色、适度降低红色和绿色。所有输出限制在各通道合法范围内，滑块表示相对调节量而非测量色温。
- 启动、换屏、唤醒不会自动应用调色。读取成功不等于写入支持，首次主动操作仍必须验证。

## 控制与错误

- 复用串行 DDC actor、命令超时、拖动防抖与忙碌态；写入固定选择的显示器 UUID，阻止跨显示器应用结果。
- 三通道写入后读取校验。部分写入失败时尽力回滚到该次写入前的值，明确显示失败及可能的回滚失败，不宣称成功。
- RGB 读取或合法性检查失败时禁用冷暖调节，显示“当前显示器或 HDR 模式不支持硬件冷暖调节”。亮度仍可独立使用。
- 不自动切换显示器图像模式、HDR 或其他系统设置。实际硬件写入验证后恢复验证前值。

## 验证与交付

- 先为 RGB 读数验证、暖冷插值、通道范围与基线恢复编写失败测试，再实现。
- 编译应用并运行全部测试；条件允许时对连接的显示器做最小幅度调色、读回、恢复测试，不能验证的部分如实记录。
- 更新中文 README 与验证说明，重新打包应用与源码，更新现有 GitHub 仓库及下载包，不上传无关项目文件。

## 自检

范围仅限硬件相对冷暖调节；不承诺显示器通用兼容、准确 Kelvin、HDR 自动解锁或软件滤镜。原色恢复、部分失败和跨屏状态均有明确处理要求。
